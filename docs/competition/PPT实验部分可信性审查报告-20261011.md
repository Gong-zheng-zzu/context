# 《忆安智护（第六改）》实验部分可信性审查报告

> 审查日期：2026-10-11  
> 审查对象：`D:/context/忆安智护（第六改）.pptx`（25 页）  
> 适用范围：强网杯现场答辩、策划书和比赛演示材料

## 结论

PPT 的实验部分方向是对的：有硬件环境、模型、数据规模和安全/检索/删除的验证主线，能够支撑“可复现、可审计”的叙事。但目前第 22 页更接近**实验协议与资源规模说明**，不是正式成绩页；第 19–21 页部分能力已经接入页面或 API，仍有受控原型和待 Docker Linux 验证的内容。

本版 PPT 可以继续作为答辩框架使用，但在补齐冻结数据集、运行配置、JSON/CSV 结果和 Docker Linux 门禁以前，不应把计划规模、历史数字或页面样例写成“当前准确率”“已完成验证”或“正式提升”。

## 建议替换的实验 PPT 结构

建议把现有实验部分拆成三页，保留原页作为技术路线背景：

### 实验协议页

标题：**实验协议：数据、对照组与验收门槛**

正文建议：

> 数据分为攻击集、正常护理集、上下文歧义集和 O-M-P-R 冻结测试集；每组独立保存 SHA-256 manifest。安全对照为 `regex_only / asdf / asdf_casia / asdf_casia_pccm`，因果对照为规则、基础模型和规则+裁决，检索对照为向量、向量+过滤和三路 RRF。正式结果同时记录配置指纹、模型版本、p50/p95 延迟、失败样本和 trace 证据。

### 当前证据页

标题：**当前已验证与受控初步结果**

建议只展示三列：

1. **已验证**：API 契约、ASDF/CASIA/PCCM-S 审计字段、因果中文 span round-trip、模型超时回退、live/fixture 边界、删除失败关闭。
2. **受控初步**：30 条 RRF 查询、历史安全纯正样本检出率、扩展页面实时接口。
3. **历史问题基线**：因果 Tuple F1 `0.5128`、延迟约 `10.6s`、删除后探针残留。

页脚固定写：**“正式成绩仅来自通过数据集、配置、来源审计和 Docker Linux 门禁的 JSON/CSV 运行产物。”**

### 待完成门禁页

标题：**发布前必须通过的证据门禁**

展示：安全正常样本误伤率、因果冻结集 F1/否定/时序、RRF 300–500 条查询、删除后探针为空、Docker Linux `go vet/go test/smoke/release_guard`。未通过项目用“待评测/未达标”显示，不用目标值替换真实结果。

## 现场演示建议

1. 先打开 live 控制台，展示 `trace_id`、模式、数据集/配置指纹和服务状态。
2. 输入一条合成护理记录，展示 ASDF/CASIA/PCCM-S 的命中与早停原因。
3. 展示 O-M-P-R 字段原文 span；无证据时展示 `needs_review` 或 abstain。
4. 展示三路结果的 `doc_id`、各来源排名、来源状态和总延迟；故障时明确显示二路/向量降级。
5. 最后做隔离用户删除验证，展示删除前后计数、检索探针、控制用户保留和证明哈希。
6. 若现场环境不可用，切换 `offline_fixture`，并明确说明夹具不调用模型、联网、存储写入或删除。

## 结论与发布建议

PPT 的技术路线和比赛叙事已经具备参赛雏形，实验部分需要从“规模与愿景”升级为“协议、证据、负结果和门禁”。在 Docker Linux 和真实三存储环境完成前，建议使用“主链已实现、部分指标待冻结评测”的表述；完成门禁后再把对应 JSON/CSV 数字替换到 PPT 和策划书中。
