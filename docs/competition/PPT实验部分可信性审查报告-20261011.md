## 1. 审查结论

PPT 的实验叙事方向正确：强调本地 Docker/Ollama、合成或脱敏数据、攻防样本和压测，能够支撑“可复现、离线优先、可审计”的比赛主线。但第 22 页目前主要是**测试资源和计划规模**，不是正式结果页；第 19、21 页的部分能力描述超过了仓库当前证据边界。

答辩时可以使用该 PPT 作为架构和实验协议说明，但不宜直接把第 22 页的样本数量、硬件和模型配置说成“已经完成的正式评测”，也不宜把静态页面上的百分比、哈希或“区块链/司法级/物理级”表述当作实测结果。正式数字必须同时绑定数据集哈希、配置指纹、运行产物、来源审计和门禁状态。

当前建议将实验相关页面改成三层：

1. **实验协议**：数据来源、切分、对照组、指标、硬件和运行命令；
2. **已验证结果**：只放 `report_eligible=true` 且有 JSON/CSV/manifest/trace 的数字；
3. **待完成或受控初步结果**：明确显示“未冻结、未复核、待 Docker Linux/Ollama 复测”，不与正式成绩并列。

## 3. 仓库现有实验结果的可引用边界

### 3.1 安全 ASDF/CASIA/PCCM-S

可核验文件：

- `docs/competition/对比实验报告.md`
- `experiments/results/raw/ablation_adversarial_security_20260921_151757Z.json`
- `experiments/datasets/external/pii_bench_zh/external_pii_positive.manifest.json`
- `experiments/datasets/external/ai4privacy_openpii/external_ai4privacy_positive.manifest.json`

目前可以说：

- 中文第三方 `pii-bench-zh` 产出 6677 条目标正样本，确定性 `asdf_casia_pccm` 检出率为 0.9422，LLM 兜底 profile 为 0.9910；这是正样本检出率，不是 accuracy/F1，且没有同分布 benign 分母。
- 内部 400 条样本曾用于安全消融；其中 benign 误报结果只适用于该内部样本和该配置，不可与中文/英文正样本拼成一个“综合准确率”。
- OpenPII 产出 14177 条英文正样本，主要用于样本量和跨语言边界分析；它是合成正样本，不构成真实护理数据外部有效性。

不能说：

- “安全准确率 95%+”或“误报率低于 1.88%”——正样本召回和内部 benign 上界来自不同分布；
- “CASIA 在所有场景提升召回”——其主要价值是抑制形状误报；
- “系统支持多语言安全检测”——英文结果暴露 ASDF 跨语言回退，项目主张仍应限定为中文护理场景。

### 3.2 因果 O-M-P-R

可核验文件：`experiments/results/raw/causal_20260726_081306Z.json`、`experiments/datasets/generated/causal_ompr_expanded_v1/manifest.json`。

- 历史 20 条 API 运行：严格 Tuple F1 `0.5128`，平均延迟约 `10.6s`，未达到目标 `F1≥0.75`、在线 `p95≤3s`。
- 扩展数据为 train 2400 / validation 400 / test 400，但 manifest 标记 `synthetic_unreviewed`、`eligible_for_frozen_evaluation=false`，不能写成冻结测试集成绩。
- 当前代码已增加 rune span、模型超时回退和默认规则/PMI/LLM 级联；这些是实现证据，不是准确率提升证据。

PPT 应显示“历史问题基线 + 当前优化状态 + 待 Docker/Ollama 正式评测”，不能只展示目标门槛。

### 3.3 三路 RRF

可核验文件：`docs/competition/对比实验报告.md`、`experiments/results/raw/retrieval_20260920_115332.json`、`experiments/results/raw/retrieval_20260920_115358.json`。

- 30 查询/30 语料的 RRF MRR `0.4172`、Recall@5 `0.6000` 是受控初步结果。
- 扩样 300 查询/500 语料得到 MRR `0.5713`、Recall@5 `0.7933`，但查询真值为 `auto_derived_unreviewed` 且 `report_eligible=false`；只能说明工程链路和定义性真值上的受控结果。
- 该查询由目标文档构造并直接包含患者姓名/日期，知识图谱路天然有利；不能据此说 RRF 对改写、指代、省略实体的查询普遍提升。
- 正式 PPT 不应把 `+20.5%` 或 `+5%` 门槛写成已通过；除非人工复核查询并通过同配置三存储、清理和来源审计门禁。

### 3.4 跨存储删除验证

可核验文件：`experiments/results/raw/unlearning_20260726_082736Z.json`。

历史试验中四类存储计数曾归零，但删除后检索探针仍返回目标 `doc_id`，所以正式称谓只能是“隔离用户/会话跨存储删除验证”，不能称“机器遗忘、参数级遗忘、物理粉碎”。代码已有 fail-closed 和证明哈希修复，仍需 Docker Linux + 真实三存储重跑后才可更新 PPT 结果。

## 4. 建议加入 PPT 的“结果卡片”格式

每张结果卡片固定包含：

```text
实验名称：安全消融 / O-M-P-R / RRF / 删除验证
证据等级：已验证结果 | 受控初步结果 | 历史问题基线
数据集：名称、版本、样本数、SHA-256
对照组：明确配置和随机种子
指标：点估计 + 置信区间 + p50/p95（如适用）
来源：JSON/CSV/manifest/trace 路径
门禁：Docker Linux、服务模式、模型/降级状态
限制：正负样本分布、人工复核、查询构造方式、失败样本
```

推荐现场展示顺序：

1. 先展示真实输入和 `trace_id`；
2. 展示 ASDF/CASIA/PCCM-S 的规则命中、归一化 span、上下文证据和早停原因；
3. 展示 O-M-P-R 候选和原文 span，遇到证据不足主动显示 `needs_review/abstain`；
4. 展示 RRF 每路状态、排名、`doc_id`、单路延迟和总延迟；
5. 最后展示删除前后计数、检索探针和证明哈希；
6. 目标值和历史值放在单独的“验收门槛/问题基线”页，不与当前运行结果混排。

## 6. 发布前必须补齐的实验

1. 在 Docker Linux 中完成 `go mod verify`、`go vet -tags http ./...`、`go test -tags http ./...` 和容器构建。
2. 启动 Qdrant、Neo4j、TimescaleDB、Ollama，执行 live smoke；保存服务版本、镜像摘要和模型清单。
3. 完成 security benign/ambiguous 人工复核，生成不可变 manifest；正样本和 benign 不跨分布拼接指标。
4. 完成因果数据双人复核、第三人仲裁，冻结 100 条测试集后再报告 Tuple F1、字段宏 F1、否定/时序和 p95。
5. 对 300 条以上人工审核查询运行向量、过滤、三路 RRF；清理、播种、top-k 和查询顺序一致，降级请求单独统计。
6. 完成删除前后探针、控制用户保留、幂等删除和证明哈希重算。
7. 重新生成 HTML/JSON/CSV 报告，再更新 PPT 和策划书中的“已验证结果”。

## 7. 推荐答辩话术

> 这页先展示实验协议和可复现数据资产，不把计划规模当成成绩。正式指标必须绑定数据集哈希、配置和运行证据。当前我们已经保留了历史问题基线，并把安全检出、因果 F1、RRF 和删除验证分别标注为已验证、受控初步或待发布门禁。现场主链只展示真实 API 的 trace、证据和降级状态；如果模型或数据库不可用，系统会如实显示失败，而不会用静态成功结果替代。

## 8. 审查后的总体评价

PPT 的技术主线和视觉叙事有比赛潜力，尤其是“安全判定 → 因果证据 → 来源审计 → 删除验证”比单纯展示 Agent 对话更有信息安全辨识度。实验部分目前最大问题不是样本数字少，而是**实验协议、历史结果和正式成绩混在一起**。完成上述证据分层并补齐 Docker Linux 实测后，PPT 就能从“技术设想展示”升级为“有边界、有失败记录、可现场复核的比赛作品”。

本审查报告不替代正式评测报告；任何新指标仍必须以运行产物和门禁状态为准。
