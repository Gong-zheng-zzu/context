# PPT 功能落地进度与参赛边界

更新时间：2026-10-11

这份记录把 PPT 中的能力映射到当前 `context-keeper-main` HTTP 主链。页面和接口优先呈现服务端真实状态，数据集、模型或存储没有通过证据门禁时，系统会显示“需要复核/受控原型”，不会把样例数字渲染成正式成绩。

## 已接入比赛主链

| PPT 能力 | 当前实现 | 现场可展示证据 | 证据边界 |
| --- | --- | --- | --- |
| ASDF/CASIA/PCCM-S 安全判定 | 受保护安全评估与四组消融接口；增加“敏感主题 + 长度/结构”语义描述规则 | 决策、命中层、置信度、早停原因、延迟、trace；语义描述可在无 Ollama 时确定性识别 | 正式安全 manifest 仍需三组独立数据和复核记录 |
| O-M-P-R 因果抽取 | 规则候选、模型/规则降级、字段 span、否定/时序质量字段、人工复核队列 | 原文 span、执行层级、降级原因、review 状态、持久化结果 | 历史 Tuple F1 约 0.513 仍是问题基线，当前未替换为正式成绩 |
| 三路 RRF 检索 | 向量、知识图谱、时间线来源审计和唯一 doc_id 融合 | 来源状态、排名、RRF 分数、单路/总延迟、降级模式 | 300 条真值仍为未复核数据，不能宣称提升 |
| 跨存储删除验证 | 删除前后计数、探针、幂等删除和证明下载 | trace、作用域哈希、证明哈希、控制数据保留结果 | 统一称为删除验证，不称参数级机器遗忘 |
| 研究 Agent | 受保护只读白名单来源接口 | 引用、抓取时间、内容哈希、执行步骤 | 不写入护理事实，不参与正式指标 |

## 已接入扩展原型

- 多模态接口只在内存中处理图像和 PCM 音频，返回脱敏副本或统计摘要；失败时返回真实错误。
- 记忆子图和风险感知重排使用 owner-scoped 证据接口，生命周期页面明确标为进程内原型。
- 黑匣子页面使用 `GET /api/v1/audit/traces/:trace_id` 读取服务端脱敏 TraceEvidence。未知 trace 或越权读取统一返回 404。
- 证据卡片使用 `GET /api/v1/evidence/summary` 读取 manifest 状态、manifest 哈希、配置指纹和能力证据等级。模板 manifest 时 `report_eligible=false`。
- `offline_fixture` 页面不会健康检查、联网、调用模型、写入、检索或删除；`live` 页面失败时显示真实错误。

本机尚未通过的发布门禁：

- Docker Linux 引擎当前不可用，尚未完成容器构建、健康检查和 live smoke。
- 安全正式 manifest 仍为 `template_only`，不能计算正式防御率、误伤率或 PII F1。
- RRF 查询真值仍带 `auto_derived_unreviewed`，不能生成正式 MRR/Recall 提升结论。

## 现场演示口径

1. 先运行控制台安全消融，说明四条链路各自的真实决策和审计证据。
2. 输入合成护理记录，展示 O-M-P-R 字段证据和人工纠错队列。
3. 只有明确勾选并输入确认短语后才允许写入或删除。
4. RRF 结果只读服务端 `retrieval_metadata`；来源缺失时展示降级模式。
5. 打开黑匣子页面查看同一 trace 的阶段状态和脱敏证据。
6. 最后展示删除验证证明，并明确说明它验证的是用户/会话范围跨存储删除。

在 Docker Linux、冻结数据集和真实三存储环境完成门禁前，PPT 中的百分比、数据规模和“正式提升”字样只能作为计划或历史基线保留。
