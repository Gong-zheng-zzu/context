# 强网杯实验协议与证据门禁

## 1. 项目定位

项目主线为“面向智慧养老的护理数据安全治理与可信辅助决策平台”。比赛现场只展示可追溯、可复现、可撤回的护理数据处理链路：

`合成或脱敏护理记录 -> ASDF/CASIA/PCCM-S -> O-M-P-R 因果证据 -> 人工纠错 -> 三存储写入 -> RRF 审计检索 -> 用户级删除证明`

系统不替代护工或医生，不输出诊断、处方或没有原文证据支持的医学机制。大模型只作为受约束的候选裁决器；联网 Agent 只作为受控的护理知识整理扩展。

## 2. 证据等级和历史基线

| 等级 | 含义 | 策划书允许的表达 |
| --- | --- | --- |
| 已验证结果 | 固定数据、配置、代码版本、原始输出和分母均可复核 | 可作为当前实验结果 |
| 受控初步结果 | 数据规模较小或真值尚未冻结 | 只能作为可行性说明 |
| 历史问题基线 | 优化前或旧路径结果 | 只能用于说明优化动机 |

当前仓库已有结果全部按上述等级标注。安全纯正样本的 94.22% 是检出率，不是准确率或 F1；30 条查询的 RRF MRR 提升 20.5% 是受控小规模结果；因果严格 Tuple F1 约 0.513、平均延迟约 10.6 秒是历史问题基线；删除实验存在删除后检索残留，只能称为跨存储删除验证。

任何正式成绩必须同时记录数据集 SHA-256、配置指纹、规则/Prompt/模型版本、容器镜像、随机种子、清理流程、运行时间和失败样本。

## 3. 五个实验包

### 3.1 安全防御与上下文误报抑制

攻击集覆盖空格或分隔符、同音替换、中文数字、Base64、语义绕过和上下文指代；另设不少于 100 条正常护理记录与不少于 100 条上下文歧义记录。对照为 `regex_only`、`asdf`、`asdf_casia`、`asdf_casia_pccm`。LLM 兜底只作为能力上限，不能替代确定性主链成绩。

报告攻击分层防御率、PII span Precision/Recall/F1、正常护理误伤率、Wilson 95% 区间、McNemar 配对检验、p50/p95 延迟、归一化步骤、span 映射、命中证据和早停原因。正式门槛为总防御率不低于 95%、各攻击类型不低于 90%、正常护理误伤率不高于 3%、PII span F1 不低于 0.92。

### 3.2 O-M-P-R 因果抽取

建立训练 600、开发 100、冻结测试 100 的分层数据集，按模板族切分，覆盖药物副作用、跌倒、压疮、感染、否定、时间顺序、多因果和无因果记录。两人独立标注，第三人仲裁后才能生成冻结测试集。

比较规则、Qwen2.5-3B、规则加 PCCM-C、Ollama 3B 裁决和通过冻结门禁后的 QLoRA 3B。每条结果必须保留 O-M-P-R 原文 span、候选关系、模型层级、否定与时序校验、拒答原因和人工纠错记录。正式门槛为严格 Tuple F1 不低于 0.75、字段宏平均 F1 不低于 0.88、无因果误报率不高于 5%、否定和时序准确率分别不低于 95%、在线 p95 不高于 3 秒。

### 3.3 三路 RRF 检索

使用同一语料、同一 top-k、同一清理流程和人工冻结真值，查询集至少 300 条，优先扩展到 500 条。比较向量、向量加过滤和真实三路 RRF，并单独记录来源为空、超时和异常时的降级结果。

每条结果固定记录唯一 `doc_id`、来源、各路排名、RRF 分数、来源状态、单路延迟和总墙钟延迟。正式门槛为 MRR 相对向量基线提升至少 5%，Recall@5 不下降；来源故障不得混入三路成功结果。

### 3.4 跨存储删除证明

以目标用户/会话和控制用户/会话为对象，记录 Qdrant、Neo4j、TimescaleDB 和缓存的删除前计数、删除后计数、删除后检索探针、第二次幂等删除、控制数据保留和哈希链审计结果。统一称为“隔离用户/会话跨存储删除验证”，不宣传参数级机器遗忘。

### 3.5 端到端比赛闭环

现场依次输入合成护理记录、查看安全判定、查看 O-M-P-R 证据、人工修改并提交复核、写入三存储、执行 RRF 审计检索、执行用户级删除并导出证明。现场单次结果只用于展示闭环，不替代冻结集统计成绩。

## 4. 研究 Agent 边界

研究 Agent 只读白名单来源，返回结构化引用、抓取时间和摘要，不能直接写入护理事实，也不参与安全、因果或 RRF 正式指标。联网不可用时切换到离线资料库，人工确认后才能形成摘要。

## 5. 六周实施和发布门禁

第一周固化数据和配置；第二周完成安全标注及消融；第三周优化因果候选、证据校验和纠错队列；第四周完成三存储、RRF 和删除证明；第五周完成单页时间线控制台和浏览器验证；第六周冻结测试集并完成 Docker/Linux 发布门禁。

每个阶段先补测试、通过专项门禁，再创建独立 Git commit。最终门禁为：

```text
go mod verify
go vet -tags http ./...
go test -tags http ./...
python -m unittest discover -s experiments/scripts -p "test_*.py"
python -m unittest discover -s experiments/training -p "test_*.py"
docker compose config --quiet
docker compose build context-keeper
python experiments/scripts/smoke_test.py --mode live
python experiments/scripts/release_guard.py
```

## 6. 不可宣称事项

在对应冻结实验完成前，不得宣称“95% 以上准确率”“因果无幻觉”“p95 小于 3 秒”“机器遗忘已完成”“司法级不可篡改”“首次提出”或“多模态已接入比赛主链”。失败样本、降级原因和负结果必须保留在报告中。
