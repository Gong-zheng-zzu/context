# 忆安智护：面向智慧养老的护理数据安全治理与可信辅助决策平台

版本：v2026.10.14-competition

## 1. 项目定位

忆安智护面向智慧养老机构的护理数据治理场景，将合成或合法脱敏的护理记录转换为可审计的安全决策、O-M-P-R 因果证据、来源可追溯的检索结果和跨存储删除验证。

系统只提供辅助整理、检索和风险提示，不替代护工、医生的诊断、处方或护理判断。比赛现场只演示一条可复现主链：

```text
护理记录 -> ASDF/CASIA/PCCM-S -> O-M-P-R 因果证据
          -> 人工复核 -> 三存储写入 -> RRF 来源审计
          -> 隔离用户/会话跨存储删除验证
```

## 2. 场景问题

养老护理记录通常分散在交接班文本、时间线、检查记录和用药记录中，具有以下治理难点：

1. 信息碎片化，事件、原因和结果难以关联。
2. 健康信息、联系方式和身份信息敏感，误检或漏检都会造成风险。
3. 护工、医生、家属和老人拥有不同访问范围，需要租户、用户和会话隔离。
4. 生成式回答容易隐藏检索来源，出现无法复核的结论。
5. 用户提出删除请求后，需要验证多个存储和缓存是否同步清理。

## 3. 系统架构

运行时采用受保护 HTTP 服务，使用 JWT 校验角色和作用域，统一生成并传递 `trace_id`。比赛主链使用 Qdrant、Neo4j、TimescaleDB 和本地审计证据；模型不可用时按规则和拒答策略降级。

所有响应记录版本、阶段状态、耗时、来源状态和配置指纹。浏览器不保存密码、JWT、密钥或真实护理原文。

## 4. 安全判定：ASDF、CASIA、PCCM-S

- ASDF 对输入执行候选 token 检测、可逆归一化和重检测，覆盖空格、符号、同音、中文数字和 Base64 等变形表达。响应保留归一化步骤、span 映射、前后哈希和攻击类型。
- CASIA 使用版本化正负关键词、上下文窗口和阈值，区分普通护理语境与真实敏感信息。响应返回命中词、窗口和误报抑制依据。
- PCCM-S 融合规则、词典、上下文和安全模型证据。正式权重只使用开发集校准，冻结测试集不调参。

系统提供 `regex_only`、`asdf`、`asdf_casia` 和 `asdf_casia_pccm` 受保护消融入口，客户端不能伪造消融结果。

## 5. O-M-P-R 因果证据

因果模块先由规则生成多候选有向边，再由本地 Qwen2.5-3B 限时裁决冲突，最后执行证据校验和规则回退。Object、Mediator、Property、Result 均保留原文 span 和 rune 偏移。

校验内容包括字段完整性、span 回取、字段顺序、否定范围、时间顺序、重复字段和证据覆盖率。校验通过才标记 `verified`；证据不足标记 `needs_review` 或 `abstain`，不凭医学常识补写机制。

医生或比赛评测角色可以提交人工复核记录。复核记录保留预测值、修正值、证据 span、版本和 trace，不直接写入训练集。

## 6. 三存储与 RRF 来源审计

每条记忆使用唯一 `doc_id`，按用户、工作区、会话和文档作用域写入三类存储。检索采用并行向量、图谱和时间线来源，并以唯一 `doc_id` 进行 RRF 融合。

每条结果固定返回命中来源、各来源排名、RRF 分数、来源状态、单路延迟、总墙钟延迟和 fusion mode。任一路为空、超时、异常或 metadata 缺失时，系统显示二路或向量回退，并从三路正式统计中单独记录。

普通 LLM 回答不能遮蔽检索来源。正式 RRF 比较必须使用同一语料、同一查询集、同一 top-k 和同一清理流程。

## 7. 跨存储删除验证

系统将删除能力称为“隔离用户/会话跨存储删除验证”。流程包含删除前计数与检索探针、四类存储删除、删除后计数、同一探针复查、控制作用域保留和第二次幂等删除。

证明响应包含 `verification_id`、`trace_id`、`verified_at`、`scope_hash`、`evidence_sha256`、各存储前后计数、探针结果和控制数据保留结果。未通过探针验证时，接口返回失败，不宣称机器遗忘、参数级遗忘或物理不可恢复。

## 8. 角色与控制台

- 护工：录入合成护理记录，查看安全判定和辅助因果提示。
- 医生：查看证据、处理因果复核队列和风险提示。
- 家属：查看最小化脱敏摘要和授权范围。
- 老人：查看授权范围并提交删除请求。
- 审计控制台：按时间线展示安全决策、因果证据、写入状态、RRF 审计和删除证明。

实时模式显示真实服务响应；离线夹具模式醒目标注，不执行模型、联网、写入、检索和删除。

## 9. 实验协议

安全实验将攻击、正常护理和上下文歧义分组，比较四种安全 profile，统计分类型防御率、PII span Precision/Recall/F1、正常误伤率、Wilson 区间、McNemar 检验和 p50/p95 延迟。

因果实验使用 train/dev/frozen-test 切分，覆盖单因果、多因果、否定、时序、药物副作用、跌倒、压疮、感染和无因果文本，统计字段宏 F1、严格 Tuple F1、无因果误报率、否定/时序准确率、证据覆盖率、拒答精度和延迟。

RRF 实验在同一语料、top-k、清理流程下比较向量基线、向量加过滤和三路 RRF，统计 MRR、Recall@5、Precision@5、nDCG@5、延迟、来源状态和租户隔离。

删除实验验证目标作用域清理、控制作用域保留、探针为空、幂等、部分失败补偿和证明链复算。

## 10. 当前结果与证据等级

本报名版不把计划规模或历史数字当作正式成绩。结果按以下等级管理：

- **已验证结果**：同时绑定数据集哈希、配置指纹、运行产物和门禁记录。
- **受控初步结果**：运行链路可复现，但数据未完成双人复核、人工相关性标注或正式 Docker/Ollama 门禁。
- **历史问题基线**：用于说明优化动机，不代表当前系统成绩。

当前可引用的受控初步结果为：在 `test_data_400.json` 上，`asdf_casia_pccm` 检出 200/200，正常样本误伤 0/200。该数据尚未完成正式双人复核，不能写成冻结集准确率或 F1。

历史因果 Tuple F1、RRF MRR 提升和删除探针结果均保留在实验报告中，不能在报名材料中写成达标成绩。正式 manifest 为 `template_only` 时，发布门禁必须拒绝生成正式报告。

## 11. 受控扩展与边界

多模态上传、记忆子图、冷热分层和研究 Agent 作为受控扩展：

- 图像和音频只做内存处理、哈希和统计摘要，不保存原始媒体。
- 记忆子图和冷热分层当前属于进程内原型，实时数据以 evidence API 为准。
- 研究 Agent 只读白名单来源，返回标题、链接、抓取时间和结构化摘要，人工确认后才形成知识摘要。
- 任何扩展都不直接写入护理事实，不参与正式安全、因果或 RRF 指标。
