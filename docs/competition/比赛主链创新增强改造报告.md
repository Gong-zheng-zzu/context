# 比赛主链创新增强改造报告

## 1. 改造目标

项目本轮收敛为可操作、可审计、可复现的护理记忆治理主链：

`护理记录 -> ASDF/CASIA/PCCM-S -> O-M-P-R -> 人工纠错 -> 三存储/RRF -> 删除验证`

系统定位是护理数据治理与可信辅助决策，不替代医生或护工，不输出诊断、处方或未经原文支持的医学机制。大模型只用于候选裁决；安全决策、因果证据、检索来源和删除结果必须能够独立审计。

## 3. 可信边界

- 公开仓库和现场演示只使用公开合成或经过人工脱敏的数据。
- 自动生成 O-M-P-R 标签一律为 `synthetic_unreviewed`；生成过程不声称人工复核。
- 两名不同成员独立复核一致，或分歧经第三人仲裁后，测试记录才可进入冻结评测；复核清单由数据集哈希和事件哈希链约束。
- 未经冻结集对比验收的 QLoRA 模型只属于训练候选，不得作为默认模型或“自研模型提升”证据。
- ASDF、CASIA 和 PCCM 是项目内的工程命名与组合设计；不使用“首次提出”“顶会水平”“必然可发表”等无法由仓库证明的表述。
- 离线夹具只验证界面和契约，不证明真实模型、三存储或删除链路可用。
- 反事实功能仅关闭已验证因果边并展示证据路径变化，不补写机制、不形成诊疗建议、不持久化为护理事实。

## 4. 分阶段实施与验收证据

| 阶段 | 核心交付 | 最低验收证据 |
| --- | --- | --- |
| 数据治理 | 未复核元数据、哈希链复核清单、冻结门禁 | 数据集 SHA-256、不同复核者、仲裁者独立性、篡改拒绝测试 |
| 攻防证据链 | trace、ASDF span 映射、CASIA 证据、PCCM-S 消融 | 受保护 API 响应、版本、配置指纹、正常样本误伤统计 |
| 因果纠错 | 多候选、证据 span、拒答、医生复核队列 | 冻结集字段指标、严格 tuple 指标、回退原因、纠错审计 |
| 检索与删除 | 三路来源审计、删除前后探针、证明书 | 唯一 doc_id、各路状态/延迟、作用域哈希、幂等删除结果 |
| 正式发布 | 同配置评测、容器门禁、浏览器验证 | 原始结果、报告门禁、测试日志、无密钥发布检查 |

每个阶段必须先完成对应测试，再建立独立 Git 提交。只有最终 Linux/Docker 门禁、认证 API 冒烟和发布安全检查全部通过后才推送公开仓库。

## 5. 本阶段完成标准

本阶段只处理可信报告和数据治理：

1. 生成数据不再伪报人工复核或仲裁状态。
2. 复核清单可检测数据篡改、事件改写、重复复核者和非独立仲裁者。
3. 未完成 100 条测试记录复核时，`test_freeze_eligible` 保持 `false`。
4. 训练文档明确 QLoRA 的候选状态和正式评测门槛。
5. 比赛材料删除或限定未经证据支持的首次性、准确率和发表级别声明。
