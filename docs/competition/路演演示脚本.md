# Context-Keeper 路演演示脚本

## 🎯 演示目标
- 时长：10-15 分钟
- 核心信息：让 AI 拥有记忆，解决上下文管理痛点
- 目标受众：投资人、企业客户、技术合作伙伴

## 📋 演示流程

### 第一部分：问题引入（2 分钟）

#### 开场白
> "大家好，我是 Context-Keeper 的创始人。今天我想问大家一个问题：**你们在使用 ChatGPT 或 Claude 时，是否遇到过这样的困扰？**"

#### 痛点演示（现场互动）
**场景 1：上下文丢失**
```
演示者："假设我现在问 ChatGPT：'我正在开发一个电商系统，使用微服务架构'"
ChatGPT："好的，我了解了"

演示者："第二天，我新建一个对话，问：'上次讨论的项目用什么架构？'"
ChatGPT："抱歉，我不记得之前的对话内容"
```

**观众痛点**：
- "对，每次都要重新说明背景，太麻烦了！"
- "我的项目信息很复杂，每次输入要 5 分钟"

**场景 2：成本高昂**
```
演示者展示数据：
"一个典型的 AI 编程助手对话：
- 第 1 次：1000 tokens
- 第 2 次：1500 tokens（包含历史）
- 第 3 次：2000 tokens
- ...
- 第 10 次：5500 tokens

每次对话都要传输完整历史，Token 消耗呈线性增长！"
```

**观众反应**：
- "我们公司每月 API 费用超过 10 万元"
- "成本确实是个大问题"

#### 解决方案引入
> "这就是为什么我们开发了 **Context-Keeper** —— 一个智能上下文记忆管理系统，让 AI 拥有真正的记忆能力。"

### 第二部分：产品演示（5 分钟）

#### Demo 1：智能记忆功能

**步骤 1：存储项目信息**
```
打开前端演示页面（使用当前实际部署的前端入口地址）。

点击 "💼 测试场景1"
发送："我正在开发一个电商系统，使用微服务架构，后端用Go语言，数据库用PostgreSQL"

系统响应：
"✅ 我已记住这个技术信息！
记录内容：我正在开发一个电商系统，使用微服务架构，后端用Go语言，数据库用PostgreSQL
✓ 已记忆"
```

**讲解要点**：
- "系统自动识别这是技术相关信息"
- "存储到长期记忆中"
- "支持语义检索，而非简单关键词匹配"

**步骤 2：跨会话检索**
```
点击 "🔍 测试记忆"
发送："刚才讨论的项目用什么技术栈？"

系统响应：
"📚 根据记忆检索到以下内容：

🧠 长期记忆：
  1. 你正在开发电商系统，使用微服务架构，后端Go语言，数据库PostgreSQL

✓ 从记忆中检索"
```

**讲解要点**：
- "即使换了新会话，系统也能记住"
- "基于语义理解，'技术栈' 和 '架构、语言、数据库' 能匹配上"
- "这就是向量检索的威力"

#### Demo 2：敏感信息自动脱敏

**步骤 1：输入敏感信息**
```
点击 "🔒 测试场景2"
发送："我的API密钥是sk-1234567890abcdefghij，数据库密码是MyP@ssw0rd123"

系统响应：
"✅ 我已记住这些信息，并自动进行了脱敏处理。

🔒 安全保护：
• 敏感信息已加密存储
• 只有授权人员可以查看原始值
• 日常检索只显示脱敏后的内容

✓ 已记忆并脱敏"
```

**讲解要点**：
- "系统自动识别 18 种敏感信息类型"
- "原始值加密存储，日常检索只显示脱敏版本"
- "降低数据泄露风险"

**步骤 2：查看脱敏效果**
```
查询："我的数据库密码是什么？"

系统响应：
"你的数据库密码是：MyP@****123（已脱敏）
如需查看完整密码，请联系管理员授权"
```
