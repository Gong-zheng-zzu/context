# PPT 功能落地矩阵（2026-10-09）

本文将《忆安智护（第六改）》中的功能逐项映射到 `context-keeper-main`，用于比赛现场和策划书的可信边界。`主链已接入` 表示存在受保护 HTTP 接口并有自动化测试；`受控原型` 表示可演示但尚未进入三存储正式指标；`页面演示` 表示页面仍需接 API；`未交付` 表示没有足够实现证据。

## 结论

比赛主链仍是：

`护理文本 → ASDF/CASIA/PCCM-S → O-M-P-R 证据 → 三路 RRF 审计 → 跨存储删除验证`

PPT 中的多模态、三维记忆、冷热分层和研究 Agent 可以作为扩展演示，但不能覆盖主链证据，也不能把受控原型的结果写成正式准确率或删除保证。

## 现场展示规则

1. 页面必须显示 `live` 或 `offline_fixture` 状态。离线夹具不能调用模型、数据库、联网 Agent、写入或删除接口。
2. 三维记忆和冷热分层只展示接口返回的 owner scope、实现类型和生命周期状态；不能把进程内状态写成 Neo4j/TimescaleDB 持久化结果。
3. 多模态接口只返回派生图像或统计摘要。原始图像、PCM、JWT 和护理原文不进入浏览器持久化。
4. RRF 只读取 `retrieval_metadata`，包括来源状态、排名、`doc_id`、RRF 分数和总延迟；不能从日志或页面固定文本推断三路成功。
5. PPT 中“司法级”“物理级机器遗忘”“100% 私有化”等表述不属于当前交付证据，策划书中只能作为后续研究方向或删除。

## 本轮交付验收

- 功能页面和控制台应从受保护 API 读取能力状态。
- 关键接口必须有单元或 HTTP 契约测试。
- 任何新增指标必须绑定数据集哈希、配置指纹和运行产物；没有这些证据时显示“未评测”。
