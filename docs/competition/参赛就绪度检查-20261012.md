## 主链当前可展示状态

现场可以展示以下闭环：

1. 输入合成护理记录并生成 `trace_id`。
2. 展示 ASDF 归一化、CASIA 上下文命中和 PCCM-S 决策。
3. 展示 O-M-P-R 候选、字段证据、模型层级和 `needs_review/abstain` 状态。
4. 明确勾选后执行三存储写入，并用服务端 `retrieval_metadata` 展示来源状态、排名和延迟。
5. 对限定评测会话执行删除前探针、跨存储删除、删除后探针和幂等验证。
6. 从门户打开比赛控制台时，JWT 只通过同源 `postMessage` 在内存中握手，不写入 URL、`localStorage` 或 `sessionStorage`。

## PPT 实验部分的判断

PPT 的实验主线是合理的，尤其是“安全判定 → 因果证据 → 来源审计 → 删除验证”比单独展示聊天 Agent 更有信息安全比赛辨识度。第 22 页适合保留为“实验协议与资源规模”，但当前文案把目标规模、运行环境和正式结果混在一起，不能直接当成绩页使用。

答辩时应把第 22 页解释为：

> 这是冻结评测前的实验协议和数据资产规划。正式成绩只在数据集复核、配置指纹、运行产物和 Docker Linux 门禁齐全后生成。

当前 PPT 需要在讲解中主动说明的边界：

- 200 份档案、500 份报表、1000 条医嘱、3000 条交互数据属于实验资源规划，仓库当前没有与这些数字一一对应的正式冻结 manifest。
- `Qwen2.5:3b` 已在 Docker 运行时连通，但本次只证明服务可用，不证明 QLoRA 模型已经通过冻结测试集门禁。
- RRF 当前真实请求返回向量回退，不能把历史小样本提升或目标阈值说成当前正式成绩。
- 因果历史 Tuple F1 约 0.513 仍是问题基线；当前代码的规则候选和回退链已能运行，但冻结集双人复核和正式 F1 尚未完成。
- 删除能力的正式称谓是“隔离用户/会话跨存储删除验证”，不应宣传为参数级机器遗忘或物理不可恢复。
- 多模态、记忆子图、冷热生命周期和研究 Agent 可以现场演示真实接口，但仍应标为受控扩展或进程内原型，不能替代三存储正式评测。

## 发布前仍必须完成

1. 为安全攻击、正常护理、上下文歧义数据完成双人复核和冲突仲裁，生成不可变 manifest。
2. 为因果数据完成 100 条冻结测试集复核，单独报告字段 F1、严格 Tuple F1、否定/时序准确率和 p95。
3. 为 RRF 完成同一语料、同一 top-k、同一清理流程下的人工审核查询集，并把降级请求从正式比较中分离。
4. 在真实三存储种子数据上完成删除后检索探针和控制用户保留验证。
5. 只有上述证据门禁通过后，才能把 PPT 中的实验规划数字替换为正式成绩。

当前结论：代码、容器和现场主链已经达到“可运行、可审计、可演示”；正式准确率、RRF 提升和删除完整率仍处于待冻结评测状态。该边界应保留在 PPT 讲稿和策划书中。
