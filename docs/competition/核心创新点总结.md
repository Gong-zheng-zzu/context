# 项目核心创新点总结

## 三大理论创新

### 1️⃣ 渐进式置信度累积模型（PCCM）

**英文名称**：Progressive Confidence Cumulation Model

**核心公式**（与 `internal/security/pccm_model.go` 的实际实现逐项一致）：
```
C_final = (Σ wᵢ·Cᵢ / Σ wᵢ) × (1 + e·(n-1))，结果截断到 [0,1]
```

- `Cᵢ`：本次实际执行层的检测置信度 ∈ [0,1]；加权平均只在置信度 > 0 的层上归一化，缺失信号不视为负证据
- `wᵢ`：各层权重（LayerWeights），权重之和无需为 1，模型内部做归一化
- `e`：多层协同增强系数 `EnhancementPerExtraLayer`，默认 **0.05**（沿用既有生产配置，非本次上调）
- `n`：置信度超过层激活阈值 `LayerActivationThreshold`（默认 **0.3**）的层数；`n = 1` 时增强因子为 1.0，单层不增强

**层结构（4 层）**：默认权重 `{1: 0.70, 2: 0.10, 4: 0.15, 5: 0.05}`，对应 Layer 1 正则 / Layer 2 词典 / Layer 4 上下文规则 / Layer 5 LLM；`n` 为超过激活阈值的层数，取值由本次实际执行层决定。Layer 3（NER）不参与执行，已从权重表移除。此前文档所述的 3 层结构与 0.1 增强系数对应的是已删除的历史实现，不再是当前口径。

**实现归一**：`ProgressiveConfidenceModel` 是安全侧置信度融合的唯一真源；`multi_layer_detector.calculateConfidenceWithPCCM` 仅委托调用它，不再持有第二套公式实现。

**创新点**：
- ✅ 提出多层检测的置信度融合数学模型
- ✅ 引入非线性增强因子，体现多层协同效应
- ⚠️ 默认使用版本化固定配置权重（`CalibrationSource` 默认 `fixed_unvalidated`）；**离线开发集校准流水线已实际跑出产物**（`internal/security/calibration/`，坐标下降搜索 `LayerWeights`）：开发集为 100 条仓库自有标注样本（`test_data_100.json`，语料 `sha256=a2240ce7…376d`，标签取自语料而非检测器反推），目标函数 `f1`，**21 次评估后未发现优于现有固定权重的配置**，故权重保持 `{1:0.70, 2:0.10, 4:0.15, 5:0.05}`，来源标注升级为可追溯的 `devset_calibrated_v1`（当前仅 `full_system` 运行配置显式加载）。校准产物需**显式加载才生效**，不声称运行时会自适应训练
- ✅ **规模与显著性（2026-09-20 扩样）**：安全消融已由 100 条扩至 **400 条**（四类别各 100；身份号按 GB 11643-1999 生成**有效校验位**，独立复核 25/25 通过）。`asdf_casia_pccm` 检测率 **0.9200**、Wilson 95% **[0.8740, 0.9502]**；200 条良性样本误报率 0.0000，Wilson 上界 **0.0188**（即真误报率低于 1.88%）。分层**精确** McNemar：`regex_only→asdf` **+80 检出、p=1.65e-24**（极显著）；`asdf→asdf_casia` **新增检出 0、p=1.0**（该语料上零效果，根因见下文 CASIA 专项实验）；`asdf_casia→pccm` **+4 检出、p=0.125（不显著）** —— 因此**不得**把 PCCM 层表述为「提升检出率」。**按绕过子类分列后**（详见 `对比实验报告.md`）：模式可检的六类（`base64` / `chinese_number` / `homophone` / `separator` / `space_separation` / `normal`）**检出率均为 100%**，16 条漏检**全部**来自 `semantic`（语义指代：只描述敏感值而不包含它）。确定性 profile 按设计排除 LLM 层，故该类**结构上不可检** —— 这是能力边界，**不是**检测器缺陷，也不得混入确定性数字
- ✅ **第三方数据集的独立验证（同日，外部 6,677 条 `pii-bench-zh`，Apache-2.0，见 `对比实验报告.md`）**：该评测**暴露并已修复**一个自建语料无法暴露的真实缺陷 —— `regex_only→asdf` 原本新增 **212** 条却**回退 162** 条（p=0.0112），而内部 400 条语料回退为 0。根因是空格/特殊字符检测器把 `/`、空格既当混淆分隔符也当字段分隔符，于是第三方文本里用 `/` 串联的多个**不同**标识符被整体合并成数字糊块，令带边界约束的正则全部失配。修复方式是为归一化加入**可证上界**（候选位数不得超过「单个」标识符上限 19 位——中国银行卡上限；超过即证明是多个标识符串接，必须原样保留且不声明为混淆样本）。**修复后回退 162 → 0**、`asdf` 检测率 **0.8667 → 0.8910**（Wilson [0.8833, 0.8982]）、新增检出 212 一条未损、p=**3.04e-64**；该上界对内部语料是**可证 no-op**（实测内部两套语料 >19 位候选数均为 0），故内部指标无需重算。`asdf→asdf_casia` 再次 **0/0、p=1.0**（第二套独立语料复现零效果；根因后经专项实验定位为三个实现缺陷，且两套语料均无误报可供抑制，见下文 CASIA 专项实验）；`asdf_casia→pccm` **+728、0 回退、p=1.42e-219**，召回达 **1.0000**（Wilson [0.9994, 1.0000]）—— 注意 PCCM 增量由 890 降至 728，差额正是 ASDF 修复后不再需要它兜底的部分，**不得**把 ASDF 的修复记作 PCCM 的功劳。**表述边界**：外部集为**纯正样本**，`1.0000` 只测召回；误报界（Wilson 上界 0.0188）来自**另一分布**的内部 200 条良性样本，**禁止合并为「第三方数据上 100% 召回且误报 <1.88%」这类联合结论**
- ✅ 渐进式检测策略，高置信度可提前终止

**学术价值**：
- 可研究方向：《基于渐进式置信度累积的多层敏感信息检测方法》；是否可投稿需由完整实验和外部评审决定
- 可申请专利：一种多层检测的置信度融合方法

**证据状态**：
- 本页只说明模型机制；准确率、误报率和性能数据须以同一数据集、同一配置的正式评测报告为准。
- 当前可现场核验的是各路证据、权重和降级状态，不把历史示例数字当作结论。

### 2️⃣ 上下文感知的敏感信息识别算法（CASIA）

**英文名称**：Context-Aware Sensitive Information Algorithm

**核心公式**：
```
C_final = C_base × W_context
W_context = 1 / (1 + e^(-Σw_i))
```

**创新点**：
- ✅ 解决"同一模式在不同上下文中含义不同"的问题
- ✅ 提出上下文关键词权重表
- ✅ 引入正负权重机制（正权重增强，负权重抑制）
- ✅ 使用sigmoid函数归一化上下文权重

**学术价值**：
- 可研究方向：《上下文感知的医疗敏感信息识别算法研究》；当前不作发表级别承诺
- 可申请专利：一种基于上下文分析的敏感信息识别方法

**证据状态**：
- 上下文权重和命中规则会随每次请求记录并可审计。
- 特别适用：身份证/邮编、手机号/工号等易混淆场景。
- **专项消融（2026-09-21，见 `对比实验报告.md`）**：在补上「语境否定」歧义样本（订单号里的身份证形状、工号里的手机号形状）并修复三个实现缺陷后，`asdf→asdf_casia` 在**不损失任何检出**的前提下把良性误报率从 **9% 降到 0%**（18 条误报全部纠正）。此前两套语料（内部 400 + 外部 6677）上「零效果」的根因是三个缺陷叠加 + 语料无误报可供抑制，**不是 CASIA 原理无效**。

**实现现状**：
- 关键词权重表已外置为 `config/casia_keywords.yaml`（默认与内置逐项一致）；
- 已**具备**可选 embedding 语义匹配能力（接口注入式，**默认关闭**）：默认走精确关键词匹配（命中记录 `MatchMethod = "exact"`，即 `strings.Contains`）；仅当显式注入相似度函数后才会出现 `"semantic"`，此时 `MatchMethod` 记录为 `semantic`。未注入时行为与纯关键词匹配完全一致。

**典型案例**：
```
案例1："患者身份证：110101199001011234"
  → 上下文关键词："身份证"（权重+1.0）
  → 判定：敏感信息 ✅

案例2："邮政编码：110101"
  → 上下文关键词："邮政编码"（权重-0.8）
  → 判定：非敏感信息 ✅
```

### 3️⃣ 对抗样本防御框架（ASDF）

**英文名称**：Adversarial Sample Defense Framework

**理论基础**：
借鉴AI安全领域的对抗学习思想，将绕过攻击视为"对抗样本"

**框架架构**：
```
输入文本
  ↓
对抗样本检测层（5种检测器）
  ├─ 空格分隔检测器
  ├─ 特殊字符混淆检测器
  ├─ 同音字替换检测器
  ├─ 中文数字检测器
  └─ Base64编码检测器
  ↓
对抗样本归一化层（还原为标准形式）
  ↓
标准检测层（正则/字典/LLM）
```

**创新点**：
- ✅ 借鉴对抗样本归一化思想处理敏感信息绕过，不作未经新颖性检索支持的"首次"声明
- ✅ 提出"检测-归一化-重检测"三步防御策略
- ✅ 可扩展的检测器架构，易于添加新的对抗样本类型
- ✅ 不只是检测，还能还原，提升后续检测准确率

**学术价值**：
- 可研究方向：《基于对抗样本防御的敏感信息检测框架》；新颖性和发表价值待检索与评审
- 可申请专利：一种对抗样本防御方法及系统
- 跨领域创新：AI安全 + 隐私保护

**证据状态**：
- 支持空格、特殊字符、中文数字和 Base64 等归一化路径；覆盖率和防御成功率须由可复现实验报告给出。

**支持的对抗样本类型**：
1. 空格分隔：`1 1 0 1 0 1` → `110101`
2. 特殊字符：`138-1234-5678` → `13812345678`
3. 同音字：`幺幺零幺零幺` → `110101`
4. 中文数字：`一一零一零一` → `110101`
5. Base64编码：`MTEwMTAx` → `110101`

### 3. 预期问题准备

**Q1: 这些创新点是你们原创的吗？**
A: PCCM、CASIA 和 ASDF 是项目内的工程命名与组合设计。ASDF 借鉴对抗样本归一化思想用于敏感信息绕过检测；答辩只主张可由代码、消融和审计证据验证的设计，不主张未经文献与专利检索证明的首次性。

**Q2: 有没有理论证明或实验验证？**
A: 我们提供了可重复运行的对比实验入口；只有在数据集、配置和清理流程校验通过后才生成定量结论。现场也可以运行攻防样例，查看真实响应和审计证据。

**Q3: 这些模型的参数是如何确定的？**
A: 当前 PCCM 和 CASIA 使用版本化固定配置权重，ASDF 使用可审计规则阈值。已建立离线开发集校准流水线（坐标下降搜索层权重），校准产物需显式加载才生效；真实开发集指标、配置指纹和冻结测试集评测完成前不替换权重，当前不声称运行时会自动训练。

**Q4: 与现有方案的本质区别是什么？**
A: 传统方案是单层检测，我们是多层融合。传统方案只看模式，我们还看上下文。传统方案被动防御，我们主动识别对抗样本。这三点是本质区别。
