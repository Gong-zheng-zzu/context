# 敏感信息检测绕过测试指南

## 测试目的
验证系统的敏感信息检测是否足够健壮，能否防止各种绕过尝试。

---

## 测试场景分类

### 1. 格式变形绕过测试

#### 1.1 添加分隔符
**目标**：测试系统是否能检测到带分隔符的敏感信息

**测试输入**：
```
张奶奶的电话是 138-1234-5678
张奶奶的电话是 138 1234 5678
张奶奶的身份证是 110101 1990 0101 1234
张奶奶的身份证是 110101-1990-0101-1234
张奶奶的银行卡是 6222 0212 3456 7890 123
```

**预期结果**：
- ✅ 应该检测到（如果正则支持）
- ❌ 可能绕过（如果正则不支持分隔符）

---

#### 1.2 全角/半角混合
**目标**：测试全角数字是否能绕过检测

**测试输入**：
```
张奶奶的电话是１３８１２３４５６７８
张奶奶的身份证是１１０１０１１９９００１０１１２３４
混合：电话是13８12３45６78
```

**预期结果**：
- ❌ 应该绕过（当前正则只匹配半角数字）
- 这是一个已知的绕过方式

---

#### 1.3 中文数字
**目标**：测试中文数字是否能绕过

**测试输入**：
```
张奶奶的电话是一三八一二三四五六七八
张奶奶的身份证是一一零一零一一九九零零一零一一二三四
```

**预期结果**：
- ❌ 应该绕过（当前系统不检测中文数字）

---

### 2. 混淆技术绕过测试

#### 2.1 零宽字符插入
**目标**：在敏感信息中插入不可见字符

**测试输入**（需要在代码中插入零宽字符）：
```python
# 在Python中生成
phone = "138" + "​" + "1234" + "​" + "5678"  # 零宽空格
print(f"张奶奶的电话是{phone}")
```

**预期结果**：
- ❌ 可能绕过（零宽字符会打断正则匹配）

---

#### 2.2 同形字符替换
**目标**：使用外观相似的字符替换数字

**测试输入**：
```
张奶奶的电话是13812З4567８  # 使用西里尔字母З替代3，全角８
张奶奶的身份证是11Ο1Ο1199ΟΟ1Ο11234  # 使用希腊字母Ο替代0
```

**预期结果**：
- ❌ 应该绕过（不是真正的数字字符）

---

#### 2.3 拆分描述
**目标**：将敏感信息拆分成多个部分

**测试输入**：
```
张奶奶的电话前三位是138，中间四位是1234，后四位是5678
张奶奶的身份证前6位是110101，出生日期是19900101，后面是1234
```

**预期结果**：
- ❌ 应该绕过（不是连续的完整格式）

---

### 3. 编码绕过测试

#### 3.1 Base64编码
**目标**：使用Base64编码敏感信息

**测试输入**：
```
张奶奶的电话是 MTM4MTIzNDU2Nzg=  (13812345678的Base64)
张奶奶的身份证是 MTEwMTAxMTk5MDAxMDExMjM0  (110101199001011234的Base64)
```

**预期结果**：
- ❌ 应该绕过（编码后不是原始格式）

---

#### 3.2 URL编码
**目标**：使用URL编码

**测试输入**：
```
张奶奶的电话是 %31%33%38%31%32%33%34%35%36%37%38
```

**预期结果**：
- ❌ 应该绕过（编码后不是原始格式）

---

### 4. 语义绕过测试

#### 4.1 间接引用
**目标**：不直接说出敏感信息，而是间接引用

**测试输入**：
```
张奶奶的电话和她的身份证号码一样，都是以138开头的
张奶奶的银行卡号就是她的手机号加上8个0
请记住这个号码：一三八一二三四五六七八
```

**预期结果**：
- ❌ 应该绕过（没有明确的敏感信息格式）

---

#### 4.2 图片/文件中的敏感信息
**目标**：将敏感信息放在图片或文件中

**测试输入**：
1. 创建一个包含身份证照片的图片
2. 创建一个包含电话号码的PDF文件
3. 上传这些文件

**预期结果**：
- ✅ 应该检测到（如果OCR功能正常）
- ❌ 可能绕过（如果OCR失败或未启用）

---

### 5. 时序绕过测试

#### 5.1 分批发送
**目标**：将敏感信息分成多条消息发送

**测试输入**：
```
消息1: 张奶奶的电话前三位是138
消息2: 中间四位是1234
消息3: 后四位是5678
```

**预期结果**：
- ❌ 应该绕过（每条消息单独看都不是完整的敏感信息）

---

#### 5.2 上下文关联
**目标**：在不同对话中逐步透露敏感信息

**测试输入**：
```
对话1: 张奶奶是1990年出生的
对话2: 她的户籍在北京东城区
对话3: 她的身份证号是110101开头的
对话4: 后面是19900101
对话5: 最后四位是1234
```

**预期结果**：
- ❌ 应该绕过（需要跨会话关联分析）

## Python测试脚本

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import requests

BASE_URL = "http://localhost:8088/api"

# 登录
login_resp = requests.post(
    f"{BASE_URL}/role/login",
    json={"role":"elder","user_id":"test_user","password":"test123","workspace_id":"default"}
)
token = login_resp.json()['data']['token']
headers = {"Authorization": f"Bearer {token}", "Content-Type": "application/json"}

# 绕过测试用例
bypass_tests = [
    ("分隔符", "电话是138-1234-5678"),
    ("空格", "电话是138 1234 5678"),
    ("全角数字", "电话是１３８１２３４５６７８"),
    ("拆分描述", "电话前三位是138，后面是12345678"),
    ("Base64", "电话是MTM4MTIzNDU2Nzg="),
]

for name, content in bypass_tests:
    resp = requests.post(
        f"{BASE_URL}/security/scan",
        json={"content": content},
        headers=headers
    )
    result = resp.json()
    detected = result.get('count', 0) > 0
    
    print(f"[{name}] {'检测到' if detected else '绕过成功'}: {content}")
    if detected:
        print(f"  检测类型: {[info['type'] for info in result.get('sensitive_infos', [])]}")
```

## 预期的绕过方式（已知弱点）

### ✅ 当前系统可以检测
1. 标准格式的敏感信息
2. 连续的数字序列
3. 文件中的文本内容（如果是纯文本）

### ❌ 当前系统可能被绕过
1. **全角数字** - 正则只匹配半角
2. **带分隔符** - 正则可能不支持
3. **零宽字符** - 会打断正则匹配
4. **拆分描述** - 不是完整格式
5. **编码后的数据** - Base64、URL编码等
6. **图片中的文字** - 依赖OCR准确性
7. **跨消息关联** - 需要上下文分析

---

## 建议的改进方向

如果发现绕过方式，可以考虑：

1. **增强正则表达式**
   - 支持分隔符：`138[-\s]?1234[-\s]?5678`
   - 支持全角数字：添加全角数字范围

2. **添加预处理**
   - 全角转半角
   - 移除零宽字符
   - 移除常见分隔符

3. **语义分析**
   - 使用NLP识别间接引用
   - 跨消息关联分析

4. **多层检测**
   - 解码后再检测（Base64、URL编码）
   - OCR后再检测（图片）
   - 拼接后再检测（拆分描述）
